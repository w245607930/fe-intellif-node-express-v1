> 建立日期：2026-08-13

## 1. 架构决策

| 编号 | 决策 | 状态 | 理由 | 后续动作 |
|---|---|---|---|---|
| ADR-001 | 第一版使用 JavaScript，不使用 TypeScript | 已确认 | 控制初版学习与配置成本，遵循原规划 | 在阶段 0 明确 JS 运行与模块规范 |
| ADR-002 | 使用 Express 构建模块化单体 | 已确认 | 结构清晰，满足当前规模且便于后续拆分 | 固定模块边界与调用方向 |
| ADR-003 | MySQL 8.x + Prisma 作为持久化方案 | 已确认 | 关系模型适合用户与 RBAC，迁移工具成熟 | 设计约束、索引、种子和迁移流程 |
| ADR-004 | Redis 同时承载缓存、令牌状态、限流、锁与 BullMQ | 已确认 | 复用基础设施，降低第一版运维复杂度 | 使用 Key 前缀隔离用途并定义 TTL |
| ADR-005 | JWT Access Token + 服务端 Refresh Token 状态 | 已确认 | 平衡无状态访问与可撤销会话 | 确定轮换、重放检测和多端登录策略 |
| ADR-006 | API 与 Worker 作为独立进程运行 | 已确认 | 隔离耗时任务，便于独立扩缩和重启 | 分别定义入口、健康检查和停机流程 |
| ADR-007 | 第一版使用 PM2 + Nginx，不使用容器 | 已确认 | 遵循原规划并降低部署复杂度 | 补齐 Linux 主机部署、回滚和备份手册 |
| ADR-008 | 将错误、响应、校验、日志前置到基础骨架 | 已确认 | 避免后续认证和 RBAC 重复重构 | 在阶段 1 实现最小闭环 |
| ADR-009 | 使用 Node.js 22.22.x 与 npm 10.9.x | 已确认 | 匹配本地已安装的 Node.js 22 LTS，并通过 engines、packageManager、`.nvmrc` 和 lockfile 固化 | 后续升级需单独验证依赖与测试 |
| ADR-010 | 使用 ESM | 已确认 | Node.js 22 原生支持，适合新项目并与现代工具链一致 | 所有源码和配置统一使用 import/export |
| ADR-011 | API 使用 `/api/v1` 版本前缀 | 已确认 | 为未来非兼容接口演进保留明确边界 | 路由与 OpenAPI 统一使用该前缀 |
| ADR-012 | Refresh Token 会话模型 | 拟定 | 单 Token/用户无法良好支持多端和重放检测 | 阶段 4 形成单独安全设计 |
| ADR-013 | P2 锁定 Prisma 6.19.3 | 已确认 | Prisma 7 默认生成 TypeScript 客户端且要求驱动适配器，与第一版纯 JavaScript 约束冲突 | 后续升级 Prisma 7 时单独评估生成和连接方案 |
| ADR-014 | MySQL 持久化 Refresh Session 安全事实 | 已确认 | 支持哈希存储、轮换链、撤销审计和多端会话，Redis 不作为唯一业务事实 | 阶段 4 冻结轮换窗口、并发会话数和重放处置 |
| ADR-015 | 软删除不释放身份唯一标识 | 已确认 | 避免用户名或邮箱重用造成身份与审计混淆 | 用户恢复和匿名化流程在用户模块设计 |
| ADR-016 | P6 默认启用 Helmet 与显式 CORS 白名单 | 已确认 | 统一安全响应头，禁止生产环境无条件跨域；代理信任、请求限制和超时集中配置 | 部署时通过环境变量注入允许来源并复核上游依赖审计 |

## 3. 假设与约束

- 第一版面向单一区域、单一 MySQL 主库和一个 Redis 逻辑部署。
- 第一版以 REST API 为主要协议。
- 项目当前尚无具体业务模块，用户与 RBAC 是基础能力和示范模块。
- 暂无 Docker 意味着本地 MySQL、Redis 的安装由开发环境自行提供，但连接方式必须配置化。
- 所有日期、状态和验收证据以仓库内文档与 Git 历史为准。

## 4. 更新规则

1. 新增重要技术选择时分配连续 ADR 编号。
2. 替换已确认决策时保留原记录并标记“已替代”，不得直接删除历史。
3. 风险分值达到 15 及以上时，相关阶段完成前必须有明确缓解和验证结果。
4. 风险关闭必须填写可验证证据，并同步到进度台账。

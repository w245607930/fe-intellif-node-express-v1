# 实施路线图

> 版本：v1.0  
> 建立日期：2026-08-13  
> 管理方式：阶段 → 里程碑 → 任务 → 验收门禁。

## 1. 执行原则

1. 每个阶段都必须产生可运行、可测试或可审查的交付物。
2. 没有满足验收门禁的阶段不得标记完成。
3. 安全、测试和文档不是收尾工作，应随功能同步推进。
4. 所有任务使用唯一编号；进度、证据和阻塞统一记录在进度台账。
5. 先建立约定和最小闭环，再扩展完整能力，避免跨阶段大规模返工。

## 3. P0：基线与决策冻结

消除会影响整个代码库的基础歧义，建立可重复安装和协作基线。

### 任务

- [x] `P0-01` 确定并锁定 Node.js LTS 版本。
- [x] `P0-02` 确定包管理器及版本，生成并提交唯一 lockfile。
- [x] `P0-03` 确定 ESM 或 CommonJS，并记录 ADR。
- [x] `P0-04` 初始化包元数据和开发、测试、生产脚本约定。
- [x] `P0-05` 配置 `.gitignore`、`.editorconfig`、环境变量示例文件。
- [x] `P0-06` 建立 Zod 环境变量校验，缺失关键配置时快速失败。
- [x] `P0-07` 配置 ESLint、Prettier 及基础 Git Hook。
- [x] `P0-08` 更新根 README，写明依赖、安装、配置和最小启动流程。

### 验收门禁

- 全新检出后可按 README 安装依赖。
- 运行时和包管理器版本不符合要求时有清晰提示。
- 格式化和 lint 命令可执行。
- 仓库中不存在真实密钥、环境文件或运行日志。

- [x] `P1-04` 提供存活检查与就绪检查接口。
- [x] `P1-05` 实现 Request ID 生成、透传和响应头回写。
- [x] `P1-06` 实现 Pino 基础日志和 HTTP 访问日志，配置敏感字段脱敏。
- [x] `P1-07` 定义应用错误基类、错误分类和错误码规范。
- [x] `P1-08` 实现全局异常处理中间件和 404 处理。
- [x] `P1-09` 实现统一成功、失败和分页响应结构。
- [x] `P1-10` 实现通用 Zod 校验中间件，覆盖 body、query、params、headers。
- [x] `P1-11` 实现 SIGTERM/SIGINT 优雅停机骨架。
- [x] `P1-12` 增加最小 HTTP 冒烟测试。

### 验收门禁

- 服务可启动并响应健康检查。
- 非法参数、未知路由和内部错误都返回约定格式。
- 请求和错误日志可用同一个 Request ID 关联。
- 日志不会输出密码、Authorization 或 Cookie 等敏感值。
- 测试可导入 `app` 而不会自动监听端口。

- [x] `P2-05` 明确软删除、审计字段、时间戳和命名规范。

## 6. P3：Redis 基础设施

### 目标

以集中、可诊断、可关闭的方式提供 Redis 基础能力。

### 任务

- [x] `P3-01` 创建 Redis 连接配置、健康检查和优雅关闭。
- [x] `P3-02` 定义环境前缀、业务域、标识和版本组成的 Key 规范。
- [x] `P3-03` 定义 TTL、序列化、空值和缓存穿透处理原则。
- [x] `P3-04` 实现缓存服务的 get/set/delete/get-or-set 能力。
- [x] `P3-05` 实现认证会话状态访问接口。
- [x] `P3-06` 实现基于原子操作的基础限流服务。
- [x] `P3-07` 实现带唯一随机值与安全释放的锁服务。
- [x] `P3-08` 定义 Redis 故障时各功能的失败开放/失败关闭策略。
- [x] `P3-09` 为 Key、TTL、限流和锁的关键行为增加测试。

### 验收门禁

- 所有 Redis Key 由统一构造器生成。
- 持久性无明确需求的 Key 必须设置 TTL。
- 锁只能由持有者释放，超时行为有测试覆盖。
- Redis 不可用时错误可识别，且不会导致进程无界重连或静默失败。

## 7. P4：认证与会话

### 目标

实现安全、可撤销、可轮换的完整用户认证闭环。

### 任务

- [x] `P4-01` 定义注册、登录、刷新、退出和当前用户接口契约。
- [x] `P4-02` 实现密码策略、bcrypt 哈希和恒定语义的登录失败响应。
- [x] `P4-03` 实现用户注册事务和重复标识冲突处理。
- [x] `P4-04` 实现短期 Access Token 签发与认证中间件。
- [x] `P4-05` 设计 Refresh Token 会话 ID、哈希存储、过期与设备信息。
- [x] `P4-06` 实现 Refresh Token 轮换和旧 Token 撤销。
- [x] `P4-07` 实现重放检测及会话族撤销策略。
- [x] `P4-08` 实现单会话退出，并预留全部会话退出能力。
- [x] `P4-09` 对登录和刷新接口增加限流。
- [x] `P4-10` 记录认证安全事件但不记录密码和完整 Token。
- [ ] `P4-11` 覆盖成功、失败、过期、撤销和重放等集成测试。

### 验收门禁

- 注册、登录、访问受保护接口、刷新和退出形成端到端闭环。
- Refresh Token 在存储层不可直接还原为客户端原值。
- 已退出或已轮换 Token 不能再次使用。
- 登录失败不会泄露用户是否存在。

## 8. P5：RBAC 权限

### 目标

实现可管理、默认拒绝、变更可及时生效的角色权限体系。

### 任务

- [ ] `P5-01` 定义权限命名规则，如 `resource:action`。
- [ ] `P5-02` 实现用户列表、详情、状态与基础管理接口。
- [ ] `P5-03` 实现角色 CRUD 与角色权限分配。
- [ ] `P5-04` 实现权限列表与受控维护策略。
- [ ] `P5-05` 实现用户角色分配和回收。
- [ ] `P5-06` 实现 `requirePermission` 授权中间件。
- [ ] `P5-07` 定义超级管理员、禁用用户和无角色用户语义。
- [ ] `P5-08` 决定权限是否缓存，并实现可靠失效策略。
- [ ] `P5-09` 对角色与权限变更记录安全审计日志。
- [ ] `P5-10` 增加允许、拒绝、权限回收和越权场景测试。

### 验收门禁

- 未认证返回认证错误，未授权返回权限错误，两者语义明确。
- 新增或回收权限后在约定时间内生效。
- 权限检查默认拒绝，接口不能因漏传权限标识而静默放行。
- 越权访问和禁用用户行为有集成测试覆盖。

### 任务

- [ ] `P6-02` 为认证、用户、角色、权限接口补齐请求、响应和错误示例。
- [ ] `P6-03` 配置 Helmet、安全响应头和明确的 CORS 白名单。
- [ ] `P6-04` 配置请求体大小、超时和代理信任策略。
- [ ] `P6-05` 完善日志字段：Request ID、用户 ID、状态码、耗时和错误栈。
- [ ] `P6-06` 定义开发与生产日志输出、轮转和保留方式。
- [ ] `P6-07` 完善健康检查但避免泄露连接凭据和内部细节。
- [ ] `P6-08` 建立错误码目录和接口契约一致性检查。
- [ ] `P6-09` 执行依赖漏洞与敏感信息检查。

### 验收门禁

- OpenAPI 的关键请求和响应与集成测试一致。
- 生产 CORS 不使用无条件通配。
- 错误日志具有诊断信息，对客户端不暴露堆栈和内部实现。

## 10. P7：队列与调度

### 目标

实现独立、幂等、可重试、可诊断的异步任务处理能力。

### 任务

- [ ] `P7-01` 设计 Queue、Job、Worker 的命名和目录规范。
- [ ] `P7-02` 建立独立 Worker 入口和 Redis 连接生命周期。
- [ ] `P7-03` 实现一个示例任务及请求侧入队流程。
- [ ] `P7-04` 定义任务 payload Schema 和向后兼容策略。
- [ ] `P7-05` 定义重试次数、指数退避、超时和并发参数。
- [ ] `P7-06` 使用幂等键或业务状态避免重复副作用。
- [ ] `P7-07` 定义失败任务保留、告警、人工重放和清理流程。
- [ ] `P7-08` 实现 API 与 Worker 的优雅停机。
- [ ] `P7-09` 将定时任务放入唯一调度进程或 BullMQ 调度机制。
- [ ] `P7-10` 验证 PM2 Cluster 下不会重复调度。

### 验收门禁

- API 与 Worker 可独立启动、停止和重启。
- 示例任务失败后按策略重试，最终失败可被定位和重放。
- 同一业务幂等键的重复任务不产生重复副作用。
- 多 API 实例不会导致定时任务重复创建。

## 13. 跨阶段持续工作

以下工作不属于单一阶段，必须持续执行：

- 依赖安全更新与许可证检查。
- 文档、OpenAPI、测试和实现同步。
- 决策、风险、阻塞和技术债登记。
- 敏感信息与日志脱敏检查。
- 数据迁移可回滚性与向前兼容审查。
- 每个合并变更的 lint、测试和最小人工验收。

## 14. 建议的下一步

从 `P0-01` 开始冻结运行时与模块制。在这些基础决策完成前，不创建大规模源码文件，以免后续围绕 import 语法、测试配置和包管理器进行无价值返工。

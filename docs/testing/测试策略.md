# 测试策略

## 本地命令

- `npm test`：运行非数据库单元与 HTTP 集成测试。
- `npm run test:coverage`：运行同一套测试并生成 `coverage/`（text、JSON、HTML）报告；核心模块最低门槛为语句 70%、分支 60%、函数 70%、行 70%。
- `npm run test:db:migrate`、`npm run test:db`：在独立且名称包含 `test` 的 MySQL 数据库上执行迁移和数据库集成测试。
- `npm run check`：依次执行 ESLint、Prettier、覆盖率测试、Prisma 校验、OpenAPI 校验和敏感信息扫描。

## 隔离与生命周期

- Vitest 通过 `tests/setup.js` 统一释放 Prisma、Redis 和 BullMQ 连接；测试不得启动真实监听端口。
- 数据库集成测试使用 `tests/integration/support/test-database.js` 的安全门禁和外键安全清理，只允许 `NODE_ENV=test` 且数据库标识包含 `test`。
- `tests/integration/support/factories.js` 提供随机后缀的用户、角色和权限工厂，避免测试之间共享业务标识。
- Redis 与队列集成测试使用随机幂等键，并在测试结束后删除 Job、关闭 Worker、QueueEvents 和连接。

## 覆盖重点

- 认证：密码策略、bcrypt 校验、JWT 签发/验证、Refresh Token 轮换和重放撤销。
- 授权：RBAC 允许与拒绝、角色撤销后的即时生效。
- 基础设施：Redis Key、限流、锁、缓存 TTL，以及 BullMQ 重试和幂等行为。
- 契约：统一响应、错误码、请求校验和 OpenAPI 路径保持一致。

## 提交门禁

Husky 的 `pre-commit` 运行 lint-staged，`commit-msg` 运行 Commitlint。提交前应确认 `npm run check` 和需要时的 `npm run test:db` 均通过，不得提交 `.env`、coverage 产物或真实凭据。

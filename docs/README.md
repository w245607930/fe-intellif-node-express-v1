## 文档目录规划

随着项目推进，按需建立以下目录，不提前制造空文档：

```text
docs/
├── README.md
├── planning/       # 解读、路线图、进度、决策与风险
├── architecture/   # 总体架构、模块边界、数据与安全设计
├── standards/      # 编码、接口、错误码、日志、Redis Key 规范
├── api/            # API 约定与接口说明
├── testing/        # 测试策略、测试数据、验收报告
└── deployment/     # 环境准备、PM2、Nginx、发布与回滚
```

## 维护规则

1. 原始技术规划作为基线输入保留，不直接承担进度管理。
2. 每完成一个任务，同步更新进度台账中的状态、日期与证据链接。
3. 影响技术路线的选择写入决策登记，避免只存在于口头沟通中。
4. 阶段必须满足验收门禁后才能标记完成。
5. 实现与文档冲突时，先确认正确行为，再同步修正文档或代码。
6. 所有项目文档统一保存在仓库内，禁止依赖外部临时记录作为唯一信息源。

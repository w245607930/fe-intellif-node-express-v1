# Redis 规范

## Key 与数据边界

- Redis Key 必须使用 `buildRedisKey()` 构造，格式为 `<app>:<environment>:<domain>:<entity>:<identifier>[:<purpose>]`。
- 每个片段使用小写 kebab-case；不得拼入完整 Token、密码、邮箱或其他敏感信息。
- Redis 仅保存缓存、临时会话加速、限流计数和锁，不作为应持久化业务事实的唯一来源。

## TTL、序列化与缓存穿透

- 缓存写入必须传入正整数 TTL；默认 TTL 为 300 秒。
- 缓存值使用 JSON 序列化；无法序列化的值不得写入缓存。
- 对确定不存在的稳定查询，后续业务模块可缓存短 TTL 的显式空值；不得把 Redis 未命中和空值混淆。
- 不得使用 `KEYS`、无界集合或无 TTL 的临时 Key。

## 限流与锁

- 限流使用 Redis Lua 原子递增并在首次写入时设置 TTL，不能拆成非原子的 `INCR` 与 `EXPIRE` 调用。
- 锁通过 `SET key token NX EX ttl` 获取，token 必须随机且唯一。
- 释放锁必须通过 Lua 比对 token；非持有者不得删除锁。

## 故障策略

| 能力 | Redis 故障策略 | 理由 |
|---|---|---|
| 普通可再生缓存 | 失败开放 | 缓存不是业务事实，调用方应回源权威数据源。 |
| 认证会话加速 | 失败开放并回源会话事实 | 不因缓存短暂故障无条件拒绝合法会话；P4 必须实现权威存储回退。 |
| 登录与刷新限流 | 失败关闭 | 安全边界不可在限流失效时静默放行。 |
| 分布式锁保护的唯一副作用 | 失败关闭 | 无法可靠互斥时不得执行可能重复的副作用。 |

Redis 客户端最多重试 3 次，且禁用离线队列；调用方必须识别异常并应用上表策略，禁止静默吞掉连接错误。

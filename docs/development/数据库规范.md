# 数据库开发规范

## 命名与字段

- Prisma 模型使用 PascalCase，字段使用 camelCase；MySQL 表和列通过 `@@map`/`@map` 映射为复数 snake_case。
- 主键使用应用侧 CUID，时间统一以 UTC 语义读写并保留毫秒精度。
- 业务实体保留 `createdAt`、`updatedAt`；可恢复实体额外使用 `deletedAt`，关联表采用硬删除。
- 用户名和邮箱在软删除后仍保留唯一占用，避免身份标识被重新注册后造成审计混淆。

## 查询约束

- 默认查询必须排除 `deletedAt` 非空记录；需要读取已删除记录时必须在 Service 中显式说明用途。
- Controller 不得直接使用 Prisma；数据库访问只能位于 Service 或基础设施层。
- 列表查询必须分页并使用稳定排序；高频过滤条件应先检查已有索引。
- 禁止拼接原始 SQL。必须使用 Prisma API、参数化 tagged template，或经过审查的迁移 SQL。

## 事务边界

- 多表写入、状态迁移和读后写操作使用 `prisma.$transaction()`。
- 事务由 Service 定义，不跨 HTTP、Redis、队列或第三方网络调用长期持有。
- 事务回调只接收事务客户端；下层函数不得回退使用全局 Prisma Client。
- 对可能产生写冲突的操作，优先依赖唯一约束并将已知冲突转换为稳定业务错误。

## Refresh Session 边界

- MySQL 保存会话身份、令牌哈希、轮换族、过期/撤销状态和必要客户端元数据。
- 明文 Refresh Token 永不持久化；Redis 后续仅承担撤销加速、短期状态和缓存，不作为唯一业务事实。
- 多端数量、轮换窗口及重放后的整族撤销策略在认证阶段形成独立安全设计。

## 测试保护

- 数据库清理仅允许在 `NODE_ENV=test` 下执行。
- 测试数据库必须位于本机，且数据库名必须包含独立的 `test` 标识。
- 约束集成测试必须使用独立测试库，不得复用开发库或生产库。
- 测试数据库只通过 `TEST_DATABASE_URL` 配置；受保护脚本校验通过后才映射为 Prisma 的 `DATABASE_URL`。
- 使用 `npm run test:db:migrate` 部署测试库迁移，使用 `npm run test:db` 串行执行数据库集成测试，使用 `npm run test:p2` 执行完整 P2 验收。
- 清理顺序固定为角色权限、用户角色、刷新会话、权限、角色、用户；每次清理前必须重新执行误库保护。
- 禁止使用 `db push`、`DROP DATABASE`、`TRUNCATE`、关闭全局外键检查或开发数据库完成约束测试。
